# Git vs SVN

## 1. Почему в Git ветвление «дешёвое», а в SVN «дорогое»?
В Git ветка — это лёгкий указатель на коммит (файл в 41 байт), создаётся мгновенно и ничего не копирует. В SVN ветка — это копия каталога на сервере (`svn copy`) в общем дереве; хоть копия и «ленивая», это серверная операция с отдельной ревизией, а слияние веток исторически сложное и требует ручного учёта.

## 2. Можно ли в SVN сделать коммит без интернета? Почему?
Нет. SVN централизованная: коммит — это запись новой ревизии на сервере. В Git полная история лежит локально, коммитить можно офлайн, а на сервер отправляется позже через `git push`.

## 3. Где SVN до сих пор может быть предпочтительнее?
- Огромные монорепозитории с бинарными файлами (игры, CAD) и блокировка файлов (`svn lock`).
- Нужен частичный checkout отдельного подкаталога и разграничение прав на уровне каталогов.
- Устаревшая корпоративная инфраструктура и процессы, завязанные на SVN.
